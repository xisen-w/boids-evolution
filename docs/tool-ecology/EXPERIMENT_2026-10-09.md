## Question and fixed first batch
Can identical, role-free agents develop persistent complementary verified capabilities and useful cross-author dependencies when reusable data workflows have repeated demand? The earlier LDB pilot did not establish adoption. We therefore distinguish this controlled mechanism study from LDB generalization.

First validate the new harness offline and with a 4-agent / 3-round engineering run (neutral and Boids). Then fix 8 agents / 6 rounds / seeds 71, 108, 2026 / local-neutral, local-boids, independent. At most six model calls per agent-round, maximum four concurrent agents, same task opportunities, same seeded ring, same private persistence and reset conversations. No retrying a completed scientific cell to improve it. API failures are retained and halt that batch rather than becoming task failures. All raw responses and partial results retained locally; publish curated sanitized evidence and actual code revision.

Every round offers six recurring families of service requests. Agents choose which capability to build or maintain; no specialist roles or author-specific task routing. A common native adapter convention makes evaluation possible, not fixed internal tool APIs: publish.json checks maps a family to a callable(rows, lookup, request). Libraries can expose any other API. Calls must return a list of dictionaries without mutating inputs. Claimed checks are independently tested on fresh inputs and varying request parameters. Semantic feedback from these DEV service requests is returned to the author and, only with the next-round package, its neighbors. No sealed original MechEnv TEST split or new LDB evaluation opened by this batch.

Six families: cleaning (normalization + missing numeric fill), revenue (missing fill + derived column), group (normalized group totals on a newly derived revenue column), monthly (date bucket + newly derived revenue totals by month/region), lookup (normalized-key ratio of newly derived revenue to lookup target), window (newly derived revenue + trailing mean). All pipelines have deterministic host reference implementations and genuine upstream-created-column dependencies. All use the same public contract; source/reference implementations and private cases are absent from model mounts.

The workload uses disclosed toy table transformations, not a new externally validated benchmark. Repeated requests vary data, fill strategy, aggregation and window. Their purpose is to expose mechanisms under controlled recurring demand. This study can find that a single generalist solves all families, that separation merely fragments competence, or that adoption stays absent.

## Controls and measurements
Local neutral and Boids have identical publication visibility and evidence fields. Only prompt-level S/A/C directional guidance differs; no claim of original continuous Boids equations. Independent agents see only their own history; merge after all rounds. Pre-round snapshots prohibit same-round information leakage. Native dependency bundles are retained, with every receipt logged.

Report per-society values, never treat tests or agent rounds as independent randomized societies: verified family coverage, per-author verified capability profile over rounds, sustained narrow contribution (the publication has exactly one completely passing family, the same family for >=3 consecutive rounds; zero or multiple passing families break the run; this is not exclusive ownership or a general expertise ranking), cumulative authored verified-profile overlap / redundant verified builders, declared and actually executed cross-author dependencies, correct service requests with cross-author calls, and perturbation-confirmed noncrashing functional contribution. Executed calls alone are not functional benefit; perturbation is posthoc mechanism evidence, not spontaneous adoption or comparative benefit.

Preserve all arms and seeds, report uncertainty descriptively at this scale. Three seeds are exploratory, not a conclusive efficacy estimate. Freeze before paid calls, do not stop at first favorable outcome, and do not merge later protocol variants into this batch. A larger confirmatory study requires a separate freeze and single-agent / centralized / equal-total-budget controls.
