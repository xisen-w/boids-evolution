## 1. 实际运行配置

- 四组：`000`、`111`、`100`、`011`，按此顺序执行；位序为 separation / alignment / cohesion。

- Separation 阈值仍为 0.3，alignment window 仍为 3；没有为制造触发或提高分数改变阈值、任务、模型或规模。
- 本机 Mac 运行主程序，生成代码在固定 Docker 镜像中隔离执行；没有将模型 key 传入工具容器。

## 6. 对原 idea 的判断与下一步

原研究链条是：局部分离引导 → 减少冗余/增加互补 → 更有用的工具库与组合 → 更强的群体能力。

本次支持的是**工程正面结果**：真实模型能完成四组链路；S/A/C 文本干预按开关发送；separation 在两个启用组均有实际触发；评分器可以识别正确、错误及非法答案；两步/三步组合确实可执行。

对“separation 提升集体效用”的科学信号仍为**无明确结论**：每组只有一个小型社会、3 轮，属于反复修复后的 dev 诊断，触发较稀疏，整体成功率也低。不能把新的 12.5% 与旧 run-11 的 2/48 直接解释为修复的因果收益——两次都重新采样了工具和答案。

已有回答与工具目录显示，一些失败确实伴随缺少任务所需的可调用能力；另一部分来自 solver 参数/组合选择错误。它们是后续分析的具体线索，不足以断定全部低分的唯一原因。没有证明减少冗余、扩大覆盖是本轮成功的因果来源，也没有得到持续邻居关系的效果或跨 agent 依赖的因果结论。

**本次决定：停止修复付费调用，不扩大实验。** 下一步应先利用这批现成记录分析 separation 的触发机会、缺失能力和组合失败，再按原 draft 的目的冻结正式实验配置。任何更大规模、阈值或研究设计变化都不属于本次 smoke 自动执行范围。不会为了让结果好看而删除失败、挑选种子或临时改任务。
