# Sales transforms

Package-root adapters all have signature `family(rows, lookup, request)` and return fresh row dictionaries. Inputs are not mutated. `clean` fills missing units (`request.fill`: zero, mean, median; all missing becomes zero) and normalizes region by strip/lower. `revenue` fills units and appends `revenue_cents = units * price_cents`, or `None` for missing operands; it preserves region as supplied. `group` and `monthly` normalize regions and derive revenue, then aggregate nonmissing revenue with `request.agg` (`sum`, `mean`, `count`). Group outputs exclude null keys and sort by stringified key(s); empty sum/count are zero and empty mean is null. Monthly uses `date[:7]`. `lookup` normalizes regions and adds revenue per exact normalized lookup-region target; unknown/null/zero targets or null revenue give null. `window` derives revenue and appends mean of nonnull revenues in the trailing `request.window` rows (default 2), preserving region as supplied.

Example: `revenue([{'region':' North ', 'units':2, 'price_cents':50}], [], {'fill':'zero'})` returns `[{'region':' North ', 'units':2, 'price_cents':50, 'revenue_cents':100}]`. Standard input dates are ISO `YYYY-MM-DD`; the module does not validate date formats. Inputs are expected to follow the service schema and valid request choices.
